# Campus Market

เว็บเดโมตลาดสินค้ามือสองในมหาวิทยาลัย นักศึกษาค้นหาสินค้า ลงประกาศขายพร้อมวิดีโอ และติดต่อผู้ขายผ่าน LINE ID, Instagram หรือเบอร์โทรเพื่อนัดรับสินค้า

Frontend ใช้ React และ JSX บน Vite นำทางด้วย React Router และจัดหน้าด้วย Tailwind CSS v4 ผ่าน `@tailwindcss/vite` หน้าเว็บใช้ `fetch` กับ `async/await` ส่งคำขอไปยัง JSON Server 0.17.4 ซึ่งบันทึกข้อมูลใน `db.json`

## ติดตั้งและรัน

ใช้ Node.js 22.12 ขึ้นไปและ npm เปิด Terminal ในโฟลเดอร์โปรเจกต์แล้วติดตั้งจาก lockfile

```bash
npm ci
```

เปิด JSON Server ใน Terminal แรก

```bash
npm run server
```

เปิด Vite ใน Terminal ที่สอง แล้วเข้า [ตลาดสินค้า](http://localhost:5173/users) หรือใช้ URL ที่ Vite แสดง

```bash
npm run dev
```

หาก PowerShell ปิดการรัน `npm.ps1` ใช้ `npm.cmd` แทน `npm` ได้ทุกคำสั่ง

ถ้าเปิด JSON Server ค้างไว้ระหว่างอัปเดตโค้ด ให้หยุดแล้วรัน `npm run server` ใหม่เพื่อโหลด middleware ก่อนเปิด [หน้าเข้าสู่ระบบ](http://localhost:5173/login)

`npm run build` สร้าง Frontend ใน `dist/` และ `npm run preview` ใช้ดูไฟล์ build ต้องเปิด JSON Server บนพอร์ต 3001 ควบคู่กัน ทั้ง Vite dev และ preview ส่งคำขอจากเบราว์เซอร์ผ่าน `/api` เพื่อใช้คุกกี้เซสชันบนต้นทางเดียวกัน

## บัญชีสำหรับเดโมในเครื่อง

| บทบาท         | ชื่อบัญชี     | รหัสผ่านทดสอบ        |
| ------------- | --------- | ------------------ |
| User (id 1)   | `student` | `campus-student-1` |
| Admin (id 99) | `admin`   | `campus-admin-99`  |

บัญชีเดโม บัญชีที่สมัคร และโปรไฟล์ผู้ขายอยู่ใน `db.json.accounts` โดยใช้ `id` เดียวกันกับที่ประกาศและรายงานอ้างถึง บัญชีที่ล็อกอินได้มี `username`, `salt` และ `hash` ส่วนโปรไฟล์ผู้ขายตัวอย่างที่ใช้แสดงชื่ออย่างเดียวเก็บ `id`, `displayName` และ `role`

ผู้เยี่ยมชมค้นหาสินค้าและดูช่องทางติดต่อได้ ล็อกอินก่อนลงขาย จัดการประกาศของตัวเอง หรือส่งรายงาน หน้าและ API ของผู้ดูแลใช้บัญชี Admin

กด **สมัครสมาชิก** จากหน้าเข้าสู่ระบบ กรอกชื่อที่แสดง ชื่อบัญชี 3–50 อักขระ และรหัสผ่าน 8–128 อักขระ ชื่อบัญชีตรวจซ้ำโดยไม่แยกตัวพิมพ์เล็กและใหญ่ เมื่อสมัครสำเร็จระบบจะเข้าสู่ระบบให้ทันทีด้วยสิทธิ์ User

เมื่อ **ลงขาย** หรือ **แก้ไขประกาศ** ให้กรอก LINE ID, ชื่อผู้ใช้ Instagram หรือเบอร์โทรอย่างน้อยหนึ่งช่อง ข้อมูลจะแสดงในหน้ารายละเอียดของประกาศนั้น

JSON Server ตรวจรหัสผ่านจากแฮชฝั่งเซิร์ฟเวอร์ ตรวจบทบาทและเจ้าของจากเซสชัน และป้องกันการรายงานซ้ำ เซสชันเก็บในหน่วยความจำและใช้ได้ 8 ชั่วโมง การปิดหรือเริ่ม JSON Server ใหม่จะทำให้ต้องเข้าสู่ระบบอีกครั้ง บัญชีที่สมัครไว้จะคงอยู่ใน `db.json` สถานะ `reserved` เป็นป้ายที่ผู้ขายเลือกเอง

## วิดีโอในประกาศ

- ในหน้า **ลงขาย** หรือ **แก้ไขประกาศ** ไปที่ **วิดีโอสินค้า (ไม่บังคับ)** แล้วกด **เลือกไฟล์วิดีโอ** เพื่ออัปโหลดไฟล์ MP4 หรือ WebM ได้ 1 ไฟล์ ขนาดไม่เกิน 50 MB จากนั้นบันทึกประกาศ
- อีกทางเลือกคือใส่ลิงก์ YouTube หรือลิงก์ตรงไปยังไฟล์วิดีโอในช่อง **หรือใส่ลิงก์วิดีโอ** หากเลือกไฟล์อยู่ ให้กด **ยกเลิกไฟล์ที่เลือก** เพื่อกลับมาใช้ช่องลิงก์
- ผู้ชมกดเล่นในส่วน **วิดีโอสินค้า** บนหน้ารายละเอียดได้ หากคลิป YouTube เล่นแบบฝังไม่ได้ ให้กด **เปิดบน YouTube**
- เปลี่ยนคลิปด้วยไฟล์หรือลิงก์ใหม่ หากต้องการนำคลิปที่อัปโหลดออก ให้กด **นำวิดีโอเดิมออก** แล้วบันทึก สำหรับคลิปแบบลิงก์ให้ล้างช่องลิงก์แล้วบันทึก

ระบบเก็บไฟล์ที่อัปโหลดบนเครื่องที่รัน JSON Server ใน `uploads/videos/` และเก็บตำแหน่งไฟล์ไว้ใน `db.json` เมื่อต้องสำรองหรือย้ายข้อมูล ให้เก็บ `db.json` และ `uploads/videos/` ไว้ด้วยกัน หลังเปลี่ยนหรือนำวิดีโอออก หรือเมื่อประกาศถูกลบ ระบบจะลบไฟล์ที่ไม่มีประกาศอ้างถึงแล้ว

## ข้อมูลและ API

| Collection | ข้อมูลตัวอย่าง                                                    | API ที่ใช้                                                                                                                                                                  |
| ---------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `accounts` | โปรไฟล์และข้อมูลเข้าสู่ระบบในรายการเดียวกัน                           | ระบบบัญชีฝั่งเซิร์ฟเวอร์ และ `GET /users` สำหรับอ่านเฉพาะ ID กับชื่อที่แสดง                                                                                                            |
| `products` | ประกาศทั้ง 5 หมวดหมู่ ช่องทางติดต่อใน `contact` และวิดีโอใน `videoUrl` | `GET /products`, `GET /products/:id`, `GET /my/products`, `GET /my/products/:id`, `GET /admin/products`, `POST /products`, `PATCH /products/:id`, `DELETE /products/:id` |
| `reports`  | รายงานที่รอตรวจสอบและตรวจสอบแล้ว                                 | `GET /my/reports`, `GET /reports` (Admin), `POST /reports`, `PATCH /reports/:id` (Admin)                                                                                 |

ใช้ `POST /auth/register` เพื่อสมัครและเริ่มเซสชัน `POST /auth/login` เพื่อเข้าสู่ระบบ `GET /auth/me` เพื่อโหลดบัญชีจากเซสชัน และ `POST /auth/logout` เพื่อยกเลิกเซสชัน ฝั่งเบราว์เซอร์เติมคำนำหน้า `/api` ให้เส้นทางเหล่านี้

`products[].contact` เก็บ `lineId`, `instagram` และ `phone` แยกตามประกาศ

`products[].videoUrl` เก็บลิงก์วิดีโอหรือเส้นทาง `/api/product-videos/<filename>` ของไฟล์ที่อัปโหลด `POST /products` และ `PATCH /products/:id` รับ JSON เมื่อส่งเฉพาะข้อมูลประกาศ รวมถึงลิงก์วิดีโอ หากส่งไฟล์ ให้นำข้อมูลประกาศเป็นข้อความ JSON ใส่ช่อง `product` และใส่ไฟล์ในช่อง `video` ของ `multipart/form-data` เมื่อแก้ไขประกาศ การเว้น `videoUrl` จะเก็บคลิปเดิม และการส่งสตริงว่างจะนำคลิปออก

`GET /product-videos/:filename` และ `HEAD /product-videos/:filename` ส่งไฟล์ที่ยังมีประกาศอ้างถึง การเล่นรองรับคำขอช่วงไบต์ วิดีโอที่อัปโหลดมากับประกาศที่ซ่อนเข้าถึงได้เฉพาะ Admin ผ่าน API นี้

`json-server.json` ตั้งให้ JSON Server เก็บรายงานเมื่อประกาศถูกลบ และโหลด `server/product-ids.cjs` เพื่อเว้นรหัสประกาศที่ยังอ้างถึงในประวัติรายงาน การจับคู่สินค้า ผู้ขาย และผู้รายงานยังใช้รหัสตัวเลขจาก `db.json` ตามเดิม

`npm run server` เปิด JSON Server ผ่าน `server/start.cjs` การสมัครเพิ่มรายการใน `accounts` ก่อนตอบสำเร็จ เมื่อแก้ไข `db.json` จากภายนอก เซิร์ฟเวอร์อ่านข้อมูลใหม่โดยไม่ตัดการเชื่อมต่อ

ตลาด หน้าประกาศของฉัน และหน้าจัดการตลาดเรียงรายการตาม ID จากมากไปน้อย ส่วนคิวรายงานรอตรวจในหน้า Admin เรียงตาม ID จากน้อยไปมาก

## ลองเดโม

1. เปิดตลาด ค้นหา `usb` แล้วเลือกหมวด **อุปกรณ์คอมพิวเตอร์** สภาพ **ใช้งานได้ดี** และช่วง 0–900 บาท จากนั้นลองล้างตัวกรอง
2. กด **ลงขาย** แล้วล็อกอินด้วยบัญชี `student` กรอกข้อมูลสินค้าและช่องทางติดต่ออย่างน้อยหนึ่งช่อง ลองเลือกคลิปแล้วบันทึก เมื่อ API บันทึกสำเร็จจะพาไป **ประกาศของฉัน** เปิดรายละเอียดของประกาศแล้วกดเล่นคลิป
3. แก้ไขชื่อ ราคา หรือวิดีโอ ลองเปลี่ยนสถานะเป็น **จองแล้ว** จากหน้าประกาศของฉัน หากต้องการลบประกาศ ให้กดยืนยันในกล่องข้อความ
4. เปิด **หูฟังไร้สายสีครีม** ที่ `/users/products/103` เพื่อตรวจข้อมูลติดต่อ แล้วกด **รายงานประกาศ** เลือกเหตุผลและส่ง ระบบตรวจเจ้าของและประวัติรายงานล่าสุดก่อนส่ง `POST /reports` พร้อมสำเนาชื่อสินค้า
5. ออกจากบัญชี User แล้วล็อกอินด้วย `admin` ไปที่ **จัดการตลาด → รายงาน** แล้วกด **ซ่อนประกาศและตรวจแล้ว** ระบบบันทึกการซ่อนก่อน แล้วบันทึกผลตรวจรายงาน หากขั้นตอนที่สองล้มเหลว หน้าจอจะแจ้งว่าซ่อนสำเร็จและให้ลองกด **ทำเครื่องหมายว่าตรวจแล้ว** อีกครั้ง
6. ออกจากระบบแล้วเปิด URL หน้ารายละเอียดของสินค้าที่ซ่อนไว้ ระบบจะแสดงข้อความว่าไม่พบสินค้า เข้าสู่ระบบด้วยบัญชี `admin` อีกครั้ง ไปที่ **จัดการตลาด → ประกาศทั้งหมด** และกด **คืนประกาศ** รีเฟรชหน้าแล้วตรวจว่ารายงานยังอยู่ในสถานะ **ตรวจสอบแล้ว**

## ผลตรวจ

ทดสอบด้วย Chrome และ JSON Server ในเครื่อง โดยสำรอง `db.json` ก่อนทดสอบและคืนไฟล์เดโมให้ตรงกับต้นฉบับแล้ว

| สิ่งที่ตรวจ                     | ผลที่พบ                                                                                                                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| เส้นทาง ตลาด และตัวกรอง       | `/` พาไปตลาด URL ที่ไม่มีแสดงหน้าไม่พบ และตลาดเรียง ID มากไปน้อย ค้นชื่อหรือรายละเอียดร่วมกับหมวดหมู่ ราคา และสภาพได้ ล้างตัวกรองได้ ตรวจช่วงราคาผิด เลข 0 และข้อความเมื่อไม่พบสินค้าแล้ว                                       |
| ลงขาย แก้ไข เปลี่ยนสถานะ และลบ | ฟอร์มแจ้งข้อมูลผิดและคงค่าที่กรอกเมื่อ API บันทึกไม่ได้ เพิ่มประกาศด้วย id ผู้ขาย 1 แก้ไขและเปลี่ยนได้ครบสามสถานะ ยกเลิกลบได้และลบจริงเมื่อยืนยัน การเปลี่ยนแปลงยังอยู่หลังรีเฟรช                                                      |
| รายละเอียดสินค้าและเจ้าของ      | แสดง LINE ID, Instagram, เบอร์โทร และจุดนัดรับตามข้อมูลผู้ขาย เจ้าของจัดการได้เฉพาะประกาศของตัวเอง ผู้เยี่ยมชมและ User เปิดดูรายละเอียดประกาศที่ซ่อนผ่าน URL ตรงไม่ได้                                                     |
| รายงานและ Admin             | ตรวจเหตุผลและรายละเอียด คงค่าที่กรอกเมื่อส่งไม่สำเร็จ กันรายงานตัวเองและรายงานซ้ำ ซ่อนและคืนประกาศได้ สถานะการขายแยกจากการซ่อน และผลตรวจยังเป็น reviewed หลังคืนประกาศ                                                 |
| ข้อผิดพลาดและประวัติรายงาน      | จำลองให้คำขอบันทึกผลตรวจล้มเหลวหลังซ่อนสำเร็จ เห็นสถานะจริงและกดบันทึกผลตรวจใหม่ได้ ตรวจผ่าน API และไฟล์ข้อมูลแล้วว่าประวัติยังอยู่เมื่อลบประกาศ และประกาศใหม่ใช้รหัสต่างจากที่ประวัติอ้างถึงแม้ปิดเปิด API ใหม่                          |
| การกู้คืนและขนาดจอ             | หยุด JSON Server จริง หน้าแจ้งปัญหา และกลับมาใช้งานได้หลังเปิดใหม่แล้วกด **ลองใหม่** การเขียนฐานข้อมูลขณะเปิดตลาดยังคงข้อความค้นหาไว้ รูปเสียใช้รูปสำรอง หน้าหลักและแท็บ Admin ผ่านการตรวจว่าเนื้อหาไม่ล้นที่ 375, 768 และ 1280 พิกเซล |
| ติดตั้งและตรวจโค้ด              | ติดตั้งใหม่ด้วย `npm ci` สำเร็จ จากนั้น `npm run build` และ `npm run lint` ผ่าน                                                                                                                            |

ตรวจการแสดงผลด้วย Chrome บน Windows ส่วนเบราว์เซอร์อื่นและอุปกรณ์จริงยังไม่ได้ทดสอบ

### ตรวจหลังเพิ่มระบบล็อกอิน

- ทดสอบใน Chrome ที่ 375 และ 1280 พิกเซล ตรวจรหัสผ่านผิด การกลับไปยังหน้าที่ต้องการหลังล็อกอิน การคงเซสชันหลังรีเฟรช การออกจากระบบ และการเปิดหน้า Admin ด้วยบัญชี User
- ทดสอบผ่าน Chrome ด้วยฐานข้อมูลสำเนา ทั้งลงขาย แก้ไข เปลี่ยนสถานะ ลบ ส่งรายงาน ตรวจรายงาน ซ่อนและคืนประกาศ และการลองใหม่เมื่อ JSON Server ยังไม่เปิด
- เรียก API โดยตรงเพื่อตรวจว่าผู้เยี่ยมชมแก้ข้อมูลไม่ได้ User จัดการประกาศของคนอื่นหรือเรียก API ของ Admin ไม่ได้ และคุกกี้เดิมใช้ต่อไม่ได้หลังออกจากระบบ ตรวจการล็อกอินผ่าน Vite Preview แล้วด้วย

### ตรวจหลังเพิ่มสมัครสมาชิก

- ทดสอบการสมัครจาก Chrome ที่ 375 พิกเซล รวมถึงรหัสผ่านยืนยันไม่ตรง การเข้าสู่ระบบอัตโนมัติ และการกลับไปยังหน้าที่ต้องการ
- ใช้ฐานข้อมูลสำเนาทดสอบชื่อซ้ำแบบต่างตัวพิมพ์ การสมัครสองบัญชีพร้อมกัน การลงขายด้วยบัญชีใหม่ และการเข้าสู่ระบบอีกครั้งหลังรีสตาร์ต JSON Server

### ตรวจหลังเพิ่มวิดีโอสินค้า

- ใช้ Chrome และฐานข้อมูลสำเนาทดสอบเลือกไฟล์ WebM ในฟอร์มลงขาย อัปโหลดผ่าน Vite และกดเล่นจากหน้ารายละเอียด ตรวจว่าไฟล์ที่บันทึกตรงกับต้นฉบับและ API ตอบ `206 Partial Content` เมื่อขอช่วงไบต์
- ตรวจการปฏิเสธไฟล์ผิดชนิดหรือเกิน 50 MB การบันทึกโดยเจ้าของ การเปลี่ยนและนำคลิปออก และสิทธิ์เข้าถึงไฟล์ของประกาศที่ซ่อน
- จำลองการเขียนฐานข้อมูลล้มเหลวระหว่างเปลี่ยนไฟล์ ยืนยันว่าประกาศยังอ้างถึงคลิปเดิมและไฟล์ใหม่ที่บันทึกไม่สำเร็จถูกลบ
- ตรวจการบันทึกลิงก์ YouTube และการแสดงเครื่องเล่นแบบฝังในหน้ารายละเอียด การเล่นคลิป YouTube จริงขึ้นกับสิทธิ์การฝังของคลิปและการเชื่อมต่อ YouTube
