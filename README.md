# Campus Market

เว็บเดโมตลาดสินค้ามือสองในมหาวิทยาลัย นักศึกษาค้นหาสินค้า ลงประกาศขาย และติดต่อผู้ขายผ่าน LINE ID หรือเบอร์โทรเพื่อนัดรับสินค้า

Frontend ใช้ React และ JSX บน Vite นำทางด้วย React Router และจัดหน้าด้วย Tailwind CSS v4 ผ่าน `@tailwindcss/vite` หน้าเว็บใช้ `fetch` กับ `async/await` ส่งคำขอไปยัง JSON Server 0.17.4 ซึ่งบันทึกข้อมูลใน `db.json`

## ติดตั้งและรัน

ใช้ Node.js 22.12 ขึ้นไปและ npm เปิด Terminal ในโฟลเดอร์โปรเจกต์แล้วติดตั้งจาก lockfile

```bash
npm ci
```

เปิด JSON Server ใน Terminal แรก

```bash
npm run server
```

เปิด Vite ใน Terminal ที่สอง แล้วเข้า [ตลาดสินค้า](http://localhost:5173/users) หรือใช้ URL ที่ Vite แสดง

```bash
npm run dev
```

หาก PowerShell ปิดการรัน `npm.ps1` ใช้ `npm.cmd` แทน `npm` ได้ทุกคำสั่ง

ถ้าเปิด Vite หรือ JSON Server ค้างไว้จากเดโมก่อนเพิ่มล็อกอิน ให้หยุดทั้งสองตัวแล้วรันใหม่เพื่อโหลด middleware และ proxy ก่อนเปิด [หน้าเข้าสู่ระบบ](http://localhost:5173/login)

`npm run build` สร้าง Frontend ใน `dist/` และ `npm run preview` ใช้ดูไฟล์ build ต้องเปิด JSON Server บนพอร์ต 3001 ควบคู่กัน ทั้ง Vite dev และ preview ส่งคำขอจากเบราว์เซอร์ผ่าน `/api` เพื่อใช้คุกกี้เซสชันบนต้นทางเดียวกัน

| `/users/products/:id`      | ดูข้อมูลสินค้า ติดต่อผู้ขาย และรายงานประกาศของคนอื่น   |
| `/login`                   | เข้าสู่ระบบด้วยบัญชีทดสอบ                         |

| `/users/my-listings`       | ดูประกาศของตัวเอง แก้ไข ลบ และเปลี่ยนสถานะการขาย |
| `/users/products/:id/edit` | แก้ไขประกาศของบัญชีที่เป็นเจ้าของ                  |
| `/admin/dashboard`         | ดูภาพรวมตลาดสำหรับ Admin                      |
| `/admin`                   | ค้นหา ซ่อน และคืนประกาศ รวมถึงตรวจรายงาน        |

## บัญชีสำหรับเดโมในเครื่อง

| บทบาท         | ชื่อบัญชี     | รหัสผ่านทดสอบ        |
| ------------- | --------- | ------------------ |
| User (id 1)   | `student` | `campus-student-1` |
| Admin (id 99) | `admin`   | `campus-admin-99`  |

ผู้เยี่ยมชมค้นหาสินค้าและดูช่องทางติดต่อได้ ล็อกอินก่อนลงขาย จัดการประกาศของตัวเอง หรือส่งรายงาน หน้าและ API ของผู้ดูแลใช้บัญชี Admin

JSON Server ตรวจรหัสผ่านจากแฮชที่แยกไว้ฝั่งเซิร์ฟเวอร์ ตรวจบทบาทและเจ้าของจากเซสชัน และป้องกันการรายงานซ้ำ เซสชันเก็บในหน่วยความจำและจะหมดเมื่อปิดหรือเริ่ม JSON Server ใหม่ บัญชีที่แสดงเป็นข้อมูลสำหรับทดสอบในเครื่อง แผนนี้ครอบคลุมการเข้าสู่ระบบด้วยบัญชีที่เตรียมไว้ ส่วนการสมัครสมาชิกใน FR-01 อยู่นอกขอบเขต สถานะ `reserved` เป็นป้ายที่ผู้ขายเลือกเอง

## ข้อมูลและ API

| Collection | ข้อมูลตัวอย่าง                        | API ที่ใช้                                                                                                                                                                  |
| ---------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `users`    | 4 โปรไฟล์จำลอง พร้อมช่องทางติดต่อผู้ขาย  | `GET /users`                                                                                                                                                             |
| `products` | ประกาศทั้ง 5 หมวดหมู่ รวมประกาศที่ถูกซ่อน | `GET /products`, `GET /products/:id`, `GET /my/products`, `GET /my/products/:id`, `GET /admin/products`, `POST /products`, `PATCH /products/:id`, `DELETE /products/:id` |
| `reports`  | รายงานที่รอตรวจสอบและตรวจสอบแล้ว     | `GET /my/reports`, `GET /reports` (Admin), `POST /reports`, `PATCH /reports/:id` (Admin)                                                                                 |

ใช้ `POST /auth/login` เพื่อเข้าสู่ระบบ, `GET /auth/me` เพื่อโหลดบัญชีจากเซสชัน และ `POST /auth/logout` เพื่อยกเลิกเซสชัน ฝั่งเบราว์เซอร์เติมคำนำหน้า `/api` ให้เส้นทางเหล่านี้

`json-server.json` ตั้งให้ JSON Server เก็บรายงานเมื่อประกาศถูกลบ และโหลด `server/product-ids.cjs` เพื่อเว้นรหัสประกาศที่ยังอ้างถึงในประวัติรายงาน การจับคู่สินค้า ผู้ขาย และผู้รายงานยังใช้รหัสตัวเลขจาก `db.json` ตามเดิม

## ลองเดโม

1. เปิดตลาด ค้นหา `usb` แล้วเลือกหมวด **อุปกรณ์คอมพิวเตอร์** สภาพ **ใช้งานได้ดี** และช่วง 0–900 บาท จากนั้นลองล้างตัวกรอง
2. กด **ลงขาย** แล้วล็อกอินด้วยบัญชี `student` กรอกข้อมูลและบันทึก เซิร์ฟเวอร์กำหนดเจ้าของจากเซสชันและตั้งสถานะพร้อมขาย เมื่อ API บันทึกสำเร็จจะพาไป **ประกาศของฉัน**
3. แก้ไขชื่อหรือราคา ฟอร์มเดียวกันส่ง `PATCH` เฉพาะรายละเอียดที่แก้ได้ ลองเปลี่ยนสถานะเป็น **จองแล้ว** จากหน้าประกาศของฉัน หากต้องการลบ ให้ยืนยันก่อนส่ง `DELETE`
4. เปิด **หูฟังไร้สายสีครีม** ที่ `/users/products/103` เพื่อตรวจข้อมูลติดต่อ แล้วกด **รายงานประกาศ** เลือกเหตุผลและส่ง ระบบตรวจเจ้าของและประวัติรายงานล่าสุดก่อนส่ง `POST /reports` พร้อมสำเนาชื่อสินค้า
5. ออกจากบัญชี User แล้วล็อกอินด้วย `admin` ไปที่ **จัดการตลาด → รายงาน** แล้วกด **ซ่อนประกาศและตรวจแล้ว** ระบบบันทึกการซ่อนก่อน แล้วบันทึกผลตรวจรายงาน หากขั้นตอนที่สองล้มเหลว หน้าจอจะแจ้งว่าซ่อนสำเร็จและให้ลองกด **ทำเครื่องหมายว่าตรวจแล้ว** อีกครั้ง
6. กลับตลาดและเปิด URL ตรงของสินค้าที่ซ่อนเพื่อดูผล จากนั้นไปที่ **Admin → ประกาศทั้งหมด** และกดคืนประกาศ รีเฟรชหน้าเพื่อตรวจว่าข้อมูลที่บันทึกยังอยู่และรายงานยังเป็นสถานะตรวจสอบแล้ว

## ผลตรวจ

ทดสอบด้วย Chrome และ JSON Server ในเครื่อง โดยสำรอง `db.json` ก่อนทดสอบและคืนไฟล์เดโมให้ตรงกับต้นฉบับแล้ว

| สิ่งที่ตรวจ                     | ผลที่พบ                                                                                                                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| เส้นทาง ตลาด และตัวกรอง       | `/` พาไปตลาด URL ที่ไม่มีแสดงหน้าไม่พบ และตลาดเรียงใหม่ก่อน ค้นชื่อหรือรายละเอียดร่วมกับหมวดหมู่ ราคา และสภาพได้ ล้างตัวกรองได้ ตรวจช่วงราคาผิด เลข 0 และข้อความเมื่อไม่พบสินค้าแล้ว                                             |
| ลงขาย แก้ไข เปลี่ยนสถานะ และลบ | ฟอร์มแจ้งข้อมูลผิดและคงค่าที่กรอกเมื่อ API บันทึกไม่ได้ เพิ่มประกาศด้วย id ผู้ขาย 1 แก้ไขและเปลี่ยนได้ครบสามสถานะ ยกเลิกลบได้และลบจริงเมื่อยืนยัน การเปลี่ยนแปลงยังอยู่หลังรีเฟรช                                                      |
| รายละเอียดสินค้าและเจ้าของ      | แสดง LINE ID เบอร์โทรและจุดนัดรับตามข้อมูลผู้ขาย เจ้าของจัดการได้เฉพาะประกาศของตัวเอง URL แก้ไขของคนอื่นถูกปฏิเสธ URL สินค้าที่ไม่มีและสินค้าที่ซ่อนแสดงข้อความแยกกัน                                                           |
| รายงานและ Admin             | ตรวจเหตุผลและรายละเอียด คงค่าที่กรอกเมื่อส่งไม่สำเร็จ กันรายงานตัวเองและรายงานซ้ำ ซ่อนและคืนประกาศได้ สถานะการขายแยกจากการซ่อน และผลตรวจยังเป็น reviewed หลังคืนประกาศ                                                 |
| ข้อผิดพลาดและประวัติรายงาน      | จำลองให้คำขอบันทึกผลตรวจล้มเหลวหลังซ่อนสำเร็จ เห็นสถานะจริงและกดบันทึกผลตรวจใหม่ได้ ตรวจผ่าน API และไฟล์ข้อมูลแล้วว่าประวัติยังอยู่เมื่อลบประกาศ และประกาศใหม่ใช้รหัสต่างจากที่ประวัติอ้างถึงแม้ปิดเปิด API ใหม่                          |
| การกู้คืนและขนาดจอ             | หยุด JSON Server จริง หน้าแจ้งปัญหา และกลับมาใช้งานได้หลังเปิดใหม่แล้วกด **ลองใหม่** การเขียนฐานข้อมูลขณะเปิดตลาดยังคงข้อความค้นหาไว้ รูปเสียใช้รูปสำรอง หน้าหลักและแท็บ Admin ผ่านการตรวจว่าเนื้อหาไม่ล้นที่ 375, 768 และ 1280 พิกเซล |
| ติดตั้งและตรวจโค้ด              | ติดตั้งใหม่ด้วย `npm ci` สำเร็จ จากนั้น `npm run build` และ `npm run lint` ผ่าน                                                                                                                            |

ตรวจการแสดงผลด้วย Chrome บน Windows ส่วนเบราว์เซอร์อื่นและอุปกรณ์จริงยังไม่ได้ทดสอบ

### ตรวจหลังเพิ่มระบบล็อกอิน

- ทดสอบใน Chrome ที่ 375 และ 1280 พิกเซล ตรวจรหัสผ่านผิด การกลับไปยังหน้าที่ต้องการหลังล็อกอิน การคงเซสชันหลังรีเฟรช การออกจากระบบ และการเปิดหน้า Admin ด้วยบัญชี User
- ทดสอบผ่าน Chrome ด้วยฐานข้อมูลสำเนา ทั้งลงขาย แก้ไข เปลี่ยนสถานะ ลบ ส่งรายงาน ตรวจรายงาน ซ่อนและคืนประกาศ และการลองใหม่เมื่อ JSON Server ยังไม่เปิด
- เรียก API โดยตรงเพื่อตรวจว่าผู้เยี่ยมชมแก้ข้อมูลไม่ได้ User จัดการประกาศของคนอื่นหรือเรียก API ของ Admin ไม่ได้ และคุกกี้เดิมใช้ต่อไม่ได้หลังออกจากระบบ ตรวจการล็อกอินผ่าน Vite Preview แล้วด้วย
